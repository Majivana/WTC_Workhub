## Design decisions

- Use a modular monolith for the MVP.
- Keep WorkPeriod targets configurable rather than hard-coding 18 hours.
- Treat evidence versions, verification history, and audit events as historical records.
- Treat selfie and location data as sensitive personal data.
- Keep historical KwantuGo references classified as current-system evidence.

## Problems and solutions

- The original attendance redesign described an external import boundary. It was replaced with
  first-party attendance sessions after the requirements changed.
- The GitHub Project board could not be managed because the token lacks Projects permissions.
- The GitHub Wiki is enabled, but its repository is not initialized and the current token could
  not create the first Wiki page. Publish-ready Wiki content is therefore maintained in
  `docs/wiki/`.
